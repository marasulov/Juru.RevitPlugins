# Изменение статуса коллизии из Ревита: запрос к бэкенду

Плагин ClashNavigator меняет статус коллизии в окне навигатора и отправляет изменение на сервер коллизий.
Ниже — контракт, который нужно реализовать на бэкенде. Клиент уже написан:
`ClashServerClient.UpdateClashStatusesAsync` (`Models/RevitClashes/Models/RevitClashReport/ServerClashes`).

## Эндпоинт

```
POST {baseUrl}/api/clashes/status
Content-Type: application/json; charset=utf-8
```

`baseUrl` — тот же адрес, с которого плагин читает `api/projects`, `api/objects/{id}/clashes`.

## Тело запроса

```json
{
  "changedBy": "JURU\\y.marasulov",
  "changedByDisplayName": "y.marasulov",
  "changedAt": "2026-08-12T07:15:42.1234567Z",
  "source": "Revit ClashNavigator",
  "items": [
    { "clashId": 1024, "status": "resolved" },
    { "clashId": 1031, "status": "approved" }
  ]
}
```

| Поле                   | Тип             | Описание                                                                                  |
|------------------------|-----------------|-------------------------------------------------------------------------------------------|
| `changedBy`            | string          | Учётная запись Windows автора изменения, `DOMAIN\user`. Берётся из `WindowsIdentity.GetCurrent().Name`, не из имени пользователя Autodesk. |
| `changedByDisplayName` | string          | Имя сотрудника, как его знает Windows — `Yusuf Marasulov` (`GetUserNameEx(NameDisplay)`). Это то имя, которое нужно показывать в интерфейсах вместо логина. Если Windows имя не отдала, здесь окажется учётная запись без домена. |
| `changedAt`            | string, ISO 8601| Момент изменения на машине пользователя, **UTC**. Сервер вправе писать в базу своё время.  |
| `source`               | string          | Источник изменения, сейчас всегда `Revit ClashNavigator`.                                  |
| `items`                | array           | Изменённые коллизии, минимум одна. Плагин копит изменения статусов в окне и отправляет их одной пачкой по кнопке «Сохранить все», поэтому в `items` может быть и одна коллизия, и несколько сотен. |
| `items[].clashId`      | long            | `Id` коллизии из `ClashViewDto` (то же значение, что вернул `GET api/objects/{objectId}/clashes`). |
| `items[].status`       | string          | Новый статус: `new`, `active`, `approved`, `resolved`.                                     |

Соответствие статусов плагина и базы:

| Статус в окне навигатора | Значение в запросе |
|--------------------------|--------------------|
| Активно                  | `active`           |
| Согласовано              | `approved`         |
| Устранено                | `resolved`         |

Статус «Нет пересечения» на сервер не отправляется: он вычисляется по геометрии в Ревите и в базе не хранится.

## Ответ

`200 OK`:

```json
{
  "updated": 2,
  "failed": []
}
```

```json
{
  "updated": 1,
  "failed": [
    { "clashId": 1031, "message": "Коллизия не найдена" }
  ]
}
```

| Поле                | Тип    | Описание                                                                          |
|---------------------|--------|-----------------------------------------------------------------------------------|
| `updated`           | int    | Сколько коллизий записано в базу.                                                 |
| `failed`            | array  | Коллизии, которые записать не удалось. Пустой массив при полном успехе.            |
| `failed[].clashId`  | long   | Id коллизии.                                                                      |
| `failed[].message`  | string | Текст, который плагин покажет пользователю в строке состояния.                     |

Непустой `failed` или код ответа не 2xx плагин показывает как ошибку отправки; локальный статус в окне при этом остаётся
изменённым и уйдёт на сервер при следующем сохранении. Частичный успех допустим: коллизии из `failed` плагин считает
неотправленными, остальные — отправленными, поэтому повтор придёт только по неудавшимся.
Тело ответа с ошибкой (текст, а не JSON) плагин тоже покажет пользователю, обрезав до 300 символов.

## Что нужно сохранить в базе

1. Новый статус коллизии.
2. Автора изменения и время: **и `changedBy`, и `changedByDisplayName`**. Логин нужен как идентификатор,
   имя — для показа пользователю (см. следующий раздел).
3. Желательно — историю: одна строка на каждое изменение (id коллизии, старый статус, новый статус, автор,
   имя автора, время, источник). Плагин историю не читает, но она нужна для разбора «кто и когда закрыл коллизию».

## Что плагин читает обратно

В `GET api/objects/{objectId}/clashes` (`ClashViewDto`) плагин ожидает три необязательных поля. Если их вернуть,
навигатор покажет их в колонках «Кем изменён» и «Когда изменён»:

```json
{
  "statusChangedBy": "AD\\y.marasulov",
  "statusChangedByName": "Yusuf Marasulov",
  "statusChangedAt": "2026-08-12T07:15:42Z"
}
```

- `statusChangedByName` — **то, чего сейчас не хватает**. Плагин показывает в колонке «Кем изменён» имя, а не логин,
  и предпочитает это поле. Пока сервер его не возвращает, после «Загрузить с сервера» в колонке снова появляется
  `AD\y.marasulov` вместо `Yusuf Marasulov`. Значение можно взять из сохранённого `changedByDisplayName` либо
  из таблицы пользователей, сопоставив `changedBy` с сотрудником — тогда в «Кем изменён» будут те же имена,
  что в `responsibleName`/`responsibles`, из одного источника.
- `statusChangedAt` — UTC: плагин переводит его в часовой пояс пользователя.

Отсутствие любого из полей ошибкой не является: без имени показывается логин, без логина — статус из базы.

## Нужно ещё: файл-источник каждого элемента коллизии

Это отдельная просьба к бэкенду, не связанная со статусами, но по тому же эндпоинту
`GET api/objects/{objectId}/clashes`.

Сейчас в ответе есть `elementIdA` и `elementIdB`, но **не сказано, какому файлу принадлежит элемент**.
Id элемента уникален внутри файла, а не между файлами, поэтому плагин вынужден искать элемент по Id
в активном документе и во всех загруженных связях, беря первое совпадение. Последствия:

- элемент может сопоставиться не с тем: у коллизии `ARC_Doors-vs-ARC_Rooms` в таблице оказывался
  `Pipe Types` из другого файла;
- бокс подрезки по такой паре получается вывернутым, и показ коллизии падал с
  `Bounding box cannot be empty` (в плагине это уже обходится, но пара всё равно неверная);
- по одному Id нельзя отличить «элемент удалён из модели» от «нужный файл не загружен».

Нужны два необязательных поля с именем файла-источника — того самого файла Revit, из которого
Navisworks взял элемент:

```json
{
  "elementIdA": "7469942",
  "sourceFileA": "BASH2-Dormitory_building-ARC-v24",
  "elementIdB": "6302267",
  "sourceFileB": "BASH2-Dormitory_building-ELE-v24"
}
```

Имя — без расширения и без суффикса локальной копии (`_отсоединено`, `_<пользователь>`): плагин
сравнивает его с заголовками открытого документа и связей, отбрасывая эти окончания сам.

Если полного имени файла нет, подойдёт и дисциплина — в ответе уже есть `disciplineA`/`disciplineB`,
и по ним имя файла собирается однозначно: `{projectName}-{objectName}-{discipline}-v{версия Ревита}`.
Тогда достаточно подтвердить, что `disciplineA` относится именно к `elementIdA` (а не к первой части
названия теста), и плагин будет искать элемент только в нужной связи.
