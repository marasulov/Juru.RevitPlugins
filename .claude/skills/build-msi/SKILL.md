# Сборка MSI и выпуск релиза

Установщики собирает пайплайн ModularPipelines в `build/`: он компилирует решение во всех
конфигурациях `Release.R*`, а затем WiX (`install/Installer.cs`) делает два MSI — для одного
пользователя и на всю машину.

Порядок ниже проверен на релизах 0.0.7 и 0.0.8. Он выстроен так, чтобы ошибки всплывали до
запуска сборки: пайплайн идёт полторы минуты, а падение на последнем шаге из-за запущенного
Ревита обесценивает весь прогон.

## 1. Убедись, что Ревит закрыт

```bash
tasklist | grep -i revit
```

Проект `Juru.RevitPlugins.App` собирается с `DeployAddin=true` и копирует файлы в папку
установленных плагинов Ревита. Пока Ревит держит эти файлы, сборка падает на заблокированном
файле. Если Ревит запущен — не запускай пайплайн, скажи об этом пользователю и дождись ответа:
закрывать Ревит за него нельзя, там может быть несохранённая модель.

## 2. Определи версию

Версия задаётся переменной окружения `Build__Version` — она перекрывает пустое значение
`Build.Version` в `build/appsettings.json`:

```bash
git tag                      # последний выпущенный тег
```

Следующий релиз — обычно patch+1 от последнего тега (`0.0.8` → `0.0.9`). Не полагайся на
GitVersion без явной версии: в репозитории режим `ContinuousDeployment`, и на ветке, отличной от
master, он добавит к версии имя ветки — в названии MSI появится мусор вроде
`0.0.9-ApprovementFromView.3`.

`appsettings.json` оставляй с пустой версией: она задаётся на один прогон, а не фиксируется в
репозитории.

## 2.5. Проверь адрес сервера в настройках

`src/Juru.RevitPlugins.App/ClashServer.json` уезжает в установщик как есть - из него плагины
берут адрес сервера коллизий и заданий на отверстия. Пустой или временный (`localhost`) адрес
означает, что у всех установивших сервер не отвечает, а понять это можно только по молчащему окну.
Перед сборкой убедись, что там стоит рабочий адрес:

```bash
cat src/Juru.RevitPlugins.App/ClashServer.json
```

Рабочий адрес - `http://10.0.0.183`. Если в файле другое, верни его перед прогоном пайплайна.

## 3. Опиши изменения в Changelog.md

Новый раздел `# <версия>` **сверху файла**, до предыдущих. Разделы внутри — по смыслу
(«Что нового», «Исправлено», группы по частям плагина), а не сплошным списком.

Для исправлений записывай **причину, а не только симптом**: «двусторонняя привязка `SelectedValue`
в шаблоне ячейки `DataGrid` не писала выбор в источник» полезнее, чем «статус не менялся».
Через месяц по такому тексту понятно, что именно уже разобрано.

Источник материала — коммиты после предыдущего тега:

```bash
git log --oneline <предыдущий-тег>..HEAD
```

## 4. Собери

Из корня репозитория:

```bash
dotnet run --project build -- pack
```

Запускай в фоне: прогон занимает около полутора минут (компиляция `Release.R23…R27` плюс WiX), а
вывод пайплайна появляется целиком в конце. Аргумент `pack` включает модули `CleanProjectModule` и
`CreateInstallerModule`; последний сам зависит от компиляции. Аргумент `publish` — это выкладка на
GitHub, к сборке установщика он не относится и просто так его добавлять не нужно.

`CleanProjectModule` **очищает `output/`**, поэтому MSI предыдущей версии оттуда исчезнут. Это
нормально: выпущенные версии живут в тегах, а не в рабочей папке.

## 5. Проверь результат

В выводе должно быть `Pipeline Completed Successfully` и строки `[Artifacts] Installer:` с обоими
файлами. Проверь и сами файлы — заодно видно время, по которому потом сверяются с установленной
сборкой:

```bash
ls -la output/*.msi
```

Ожидается два файла, оба примерно по 21 МБ:

- `Juru.RevitPlugins-<версия>-SingleUser.msi` — в `%AppData%\Autodesk\Revit\Addins`, без прав администратора
- `Juru.RevitPlugins-<версия>-MultiUser.msi` — в `%ProgramData%\Autodesk\Revit\Addins`

Если версия в имени файла не та, что ты задавал, значит `Build__Version` не доехала до пайплайна —
проверь, что переменная выставлена в том же вызове оболочки, что и `dotnet run`.

## 6. Закоммить и поставь тег

```bash
git add -A
git commit    # описание изменений; в конце строка Co-Authored-By, как принято в репозитории
git tag -a <версия> -m "Release <версия>"
```

Тег ставь **аннотированный** и на тот коммит, из которого собраны MSI. Если changelog правился уже
после сборки, пересобирать не нужно: он не попадает в пакет и на бинарники не влияет — но скажи об
этом пользователю прямо, чтобы не было сомнений.

Пушить и сливать в master без отдельной просьбы не нужно.

## Что сказать пользователю про установку

Эти два пункта уже приводили к разбору «почему установилось, а работает по-старому», поэтому
повторяй их с каждым релизом:

1. **Почистить папку прошлой установки** — `%AppData%\Roaming\Autodesk\Revit\Addins\<год>\Juru.RevitPlugins.App\`.
   MSI выполняет обновление, но файлы предыдущих версий не удаляет. Там остаются сборки от времён
   до ILRepack (`Juru.RevitPlugins.ClashNavigator.dll`, `dosymep.*`, `Ninject*.dll`,
   `DevExpress.Xpf.Core.*.dll`), и .NET разрешает сборки по простому имени — именно эти остатки
   возвращают конфликт зависимостей, ради которого ILRepack и добавляли.
2. **Ревит должен быть закрыт при установке.**

И предупреди, что установщик вернёт `Juru.RevitPlugins.App.addin` в папку `Addins\<год>`: кнопки на
ленте заработают, но цикл отладки через AddinManager снова начнёт загружать сборки дважды, и для
него манифест придётся переименовать в `.addin.off`.

## Если сборка упала

- **Заблокированный файл при копировании в папку плагинов** — запущен Ревит. Закрыть и повторить.
- **Ошибка компиляции только в одной конфигурации `Release.R2X`** — код использует API, которого в
  этой версии Ревита нет. Смотри `#if REVIT****_OR_GREATER` в задетом файле; поддерживаемые
  конфигурации перечислены в `Configurations` в csproj.
- **WiX не нашёл файлы** — сначала посмотри, прошёл ли `CompileProjectModule`: `CreateInstallerModule`
  берёт готовый выход `Juru.RevitPlugins.App`, и падение здесь обычно означает, что компиляция
  отдала не то, что ожидалось.
