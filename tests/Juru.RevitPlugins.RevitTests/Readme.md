# Тесты внутри Ревита

```bash
dotnet run -c Debug.R24 --project tests/Juru.RevitPlugins.RevitTests
```

Прогон сам запускает установленный Ревит того года, что в конфигурации (`Debug.R24`, `Debug.R26`,
`Debug.R27`...), и выполняет тесты в его потоке API
([Nice3point.TUnit.Revit](https://github.com/Nice3point/RevitUnit)). Открывать Ревит заранее не
нужно, уже открытый не мешает. Полный прогон занимает около минуты. Отчёт лежит в
`bin/<конфигурация>/TestResults/*.html`.

Запускать через `dotnet run`, не `dotnet test`. С SDK .NET 10 `dotnet test` для TUnit требует
режима Microsoft.Testing.Platform в `global.json`, а он переключит на себя весь репозиторий
вместе с xUnit-тестами из CI. В Rider нужно включить *Testing Platform support*
(Settings > Build, Execution, Deployment > Unit Testing > Testing Platform).

## Что нужно на машине

- Лицензированный Ревит нужного года. Если при старте всплывёт окно лицензии, прогон зависнет,
  пока окно не закроют. Поэтому в CI эти тесты не запускаются: на раннере GitHub Ревита нет.
- Русские шаблоны Ревита `C:\ProgramData\Autodesk\RVT <год>\Templates\Russian`. Без шаблонов
  тесты пропускаются, а не падают.
- Для теста расстановки заданий на отверстия нужна библиотека семейств заданий на общем диске
  (`OpeningsConfig.FamilyLibraryPath`). Без неё этот тест пропускается.

## Что покрыто

Логика команд вызывается напрямую, без окон и выбора мышью. Модель тест строит сам: из шаблона, в
новом документе, файлы сохраняет во временную папку.

| Плагин | Команда | Что проверяется |
|---|---|---|
| Openings | PlaceOpeningTasksCommand | Поиск пересечений со стеной из связи КР. Размер задания с зазором. Отказ для воздуховода вдоль стены. Порог наименьшего сечения. Связь с неузнанной дисциплиной. Повторная расстановка не дублирует задание. |
| ClashNavigator | FindClashesCommand | Сравнение с прошлым прогоном: пара в обратном порядке не новая. Перенос статуса, имени и комментариев. Чтение элемента в `ElementModel`. |
| ProjectSetup | RunProjectSetupJobsCommand | Этап А: базовые файлы и связи в генплане, без `.0001`. Конфликт с существующим файлом. Нехватка шаблона: не создаётся ничего. Этап Б: координаты и имя площадки с базового файла (поворот 30°, отметка 5.5 м), связь с базовым. Базовый файл без площадки. |
| Schedules | CopyScheduleToDraftingViewCommand, UpdateScheduleCopyCommand | Английская копия на чертёжном виде по глоссарию. Без глоссария текст остаётся русским и попадает в отчёт. Связь копии с оригиналом через Extensible Storage. |

## Чего нет

- Окна, ViewModel и всё, что ждёт действий пользователя (`PickObjects`, TaskDialog).
- Обмен с серверами (ClashTracker, сервер заданий на отверстия, DeepL/Google).
- Поиск коллизий целиком: `RevitRepository` строится только от `UIApplication` с активным
  документом, а в тестах интерфейса Ревита нет.
- Команды, которые получают `UIDocument` (`EnglishSetBuilder`, `SheetScheduleCopyService`).

## Как устроен проект

- `InternalsVisibleTo` в ClashNavigator и ProjectSetup открывает тестам их internal-классы.
- ProjectSetup подключён под псевдонимом `extern alias ProjectSetup`. Оба плагина несут свои копии
  служебных типов Polyfill, и в общем пространстве имён они конфликтуют.
- На net48 (Ревит 2023–2024) явно подключены `Microsoft.Bcl.AsyncInterfaces`,
  `System.Text.Json` и `System.Text.Encodings.Web` 10.0.12. Без них не генерируются
  перенаправления сборок, и прогон падает на старте с `FileLoadException`.
- Каждый тест работает в своей временной папке с уникальным суффиксом в именах файлов: Ревит не
  держит открытыми два документа с одинаковым именем файла.
